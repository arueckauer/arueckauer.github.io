PHPCS Optimization on Windows: From 41 Minutes to 3 Seconds

As projects grow, tool performance can silently degrade until it becomes unbearable. I recently hit a wall where phpcs (PHP CodeSniffer) took over 41 minutes to run on a Windows machine. For a local feedback loop, this is a productivity killer.

After a few optimizations, I managed to get the execution time down to under 1 minute (cold) and ~3.3 seconds ( cached). Here is how.

The Analysis

The project consists of about 3,549 files and roughly 176k lines of code (LOC). While substantial, it shouldn’t justify a 41-minute wait.

Performance Benchmarks

  • Initial state: +41 min
  • After optimization (no cache): 53.79 sec
  • After optimization (with cache): 3.3 sec

The massive gap between the initial state and the optimized cached state suggested that not only was the execution itself slow, but the caching mechanism was failing entirely on Windows.

Why was it slow?

On Windows, several factors often conspire against PHP tools:

  1. Process Interference: Background processes (like Windows Defender) locking files during the high-I/O scan of phpcs.
  2. Cache Invalidation: A known quirk where certain file naming patterns or permissions prevent phpcs from reusing the .phpcs-cache file, forcing a full scan every time.
  3. Xdebug Overhead: Even if not actively debugging, the Xdebug extension adds significant overhead to PHP execution.

Applied Solutions

To fix this, I implemented a multi-layered approach involving OS configuration, tool settings, and shell aliases.

1. Windows Defender Exception

Exclude your project directory from real-time scanning. This is the single biggest “quick win” for I/O performance on Windows.

  • Path: C:\source (or your specific project root).

2. Fix the Cache File

There were issues with the default hidden file .phpcs-cache not being reused correctly. Renaming it to a standard file name resolved this.

  • Action: Change the cache config to phpcs-cache.
  • Git: Add phpcs-cache to your global or project ~/.gitignore to avoid committing local cache state.

3. Disable Xdebug for CLI Tools

Xdebug should be off by default for static analysis. You can do this inline using the -d flag.

php -d xdebug.mode=off vendor/bin/phpcs

4. PowerShell Aliases for Speed

To make this permanent and easy to use, I updated my PowerShell profile with aliases for all Software Quality (SQ) tools. These aliases ensure Xdebug is always off and parameters are passed through.

Remove-Item alias:r -ErrorAction SilentlyContinue

function a { php -d xdebug.mode=off vendor/bin/psalm $args }
function f { php -d xdebug.mode=off vendor/bin/phpcbf $args }
function r { php -d xdebug.mode=off vendor/bin/rector $args }
function s { php -d xdebug.mode=off vendor/bin/phpcs $args }
function t { php -d xdebug.mode=off vendor/bin/phpunit $args }

Now, running s triggers a lightning-fast, cached PHPCS check.
